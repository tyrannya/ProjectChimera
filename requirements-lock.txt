# Locked dependency set for ProjectChimera CI and Linux deployment.
#
# WHAT THIS IS. Every package the supported resolution installs for
# `pip install -e ".[all]"` on **Linux / CPython 3.11**, pinned to the exact
# version that resolution produced, taken from a green CI run rather than from
# one developer's machine. The `Tests` job installs from this file so that a
# dependency release cannot change what the suite ran against between one
# commit and the next.
#
# PLATFORM SCOPE. This lock is Linux-specific and deliberately so. It pins
# `torch==2.14.0+cpu`, which is published by the PyTorch CPU index and not by
# PyPI, and it carries Linux-only wheels (`nvidia-nccl-cu12`, `uvloop`). The
# Windows leg of the test matrix therefore resolves from `pyproject.toml`
# instead: a single lock file cannot describe two platforms, and generating a
# faithful Windows lock requires resolving on Windows. Windows is still pinned
# by `pyproject.toml`'s own bounds; it is not pinned to exact versions here.
#
# HOW TO INSTALL FROM IT. The `+cpu` build needs the PyTorch index alongside
# PyPI:
#
#     pip install --extra-index-url https://download.pytorch.org/whl/cpu \
#         -r requirements-lock.txt
#     pip install -e . --no-deps
#
# HOW TO REGENERATE IT. Bump the bounds in `pyproject.toml`, let CI resolve
# them, and copy the `Show resolved versions` table from the green `Tests` job.
# Regenerating from a developer machine is wrong unless that machine is Linux
# with CPython 3.11 and can reach the PyTorch CPU index.
#
# `projectchimera` itself is absent on purpose: it is installed from the
# checkout with `-e .`, not from an index.
